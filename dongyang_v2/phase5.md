# Phase 5: 백엔드 통합 및 프론트엔드 완성

## 목표

이 단계의 핵심 목표는 기존에 분리되어 있던 FastAPI와 Flask 백엔드를 하나로 통합하고, 미완성이었던 프론트엔드 기능을 완성하여 단일하고 응집력 있는 풀스택 애플리케이션을 구축하는 것입니다. 이를 통해 아키텍처를 단순화하고, 배포 및 유지보수 복잡성을 낮추며, 사용자 경험을 완성합니다.

## 주요 변경 사항

### 1. 백엔드 아키텍처 통합

- **FastAPI로 단일화:** 기존에 RAG API를 담당하던 FastAPI와 인증을 담당하던 Flask 서버를 **단일 FastAPI 애플리케이션으로 통합**했습니다.
- **Flask 관련 코드 제거:** `YangdongYi-front/app.py`와 `YangdongYi-front/requirements.txt`를 포함한 모든 Flask 종속성을 제거하여 프로젝트 구조를 명료화했습니다.

### 2. 인증 시스템 교체 및 강화

- **JWT 도입:** 기존의 Flask 세션 기반 인증을 **상태 비저장(Stateless) JWT (JSON Web Token) 인증 방식으로 교체**했습니다.
  - `python-jose` 라이브러리를 사용하여 토큰 생성 및 검증 로직을 구현했습니다.
  - 이를 통해 API 서버의 확장성을 확보하고, 모든 API 요청은 토큰 기반으로 안전하게 보호됩니다.
- **사용자 DB 연동:** 사용자 정보 저장을 위해 **MySQL 데이터베이스**를 공식적으로 도입하고, 관련 설정을 `.env` 파일로 관리하도록 표준화했습니다.
- **비밀번호 해싱:** `bcrypt`를 사용하여 사용자의 비밀번호를 안전하게 해싱하여 데이터베이스에 저장합니다.

### 3. 데이터베이스 스키마 통일

- **ChromaDB로 표준화:** 프로젝트 초기 `README.md`와 일부 코드에 혼용되어 언급되던 `FAISS` 관련 내용을 모두 제거하고, **`ChromaDB`를 공식 벡터 스토어로 확정**했습니다.
- **불필요한 의존성 제거:** 사용되지 않는 `pymongo` 라이브러리를 `requirements.txt`에서 제거했습니다.

### 4. 프론트엔드 기능 완성

- **실시간 채팅 UI 구현:** `main.html`에 사용자와 챗봇의 대화를 표시하는 **채팅 인터페이스를 구현**했습니다.
  - 사용자의 질문과 챗봇의 답변(근거 자료 포함)이 화면에 동적으로 렌더링됩니다.
- **API 연동:**
  - **로그인:** `login.html`에서 `/api/login` API를 호출하고, 성공 시 반환된 JWT 토큰을 `localStorage`에 저장하여 인증 상태를 유지합니다.
  - **챗봇:** `main.html`의 전송 버튼 클릭 시, `localStorage`에 저장된 토큰을 `Authorization` 헤더에 담아 `/api/v1/chat` API를 호출하도록 `send()` 함수를 구현했습니다.
  - **사용자 정보:** 페이지 로드 시 `/api/me` API를 호출하여 사용자 정보를 가져와 UI에 표시하고, 토큰이 없거나 유효하지 않을 경우 로그인 페이지로 리디렉션합니다.

## 결과

- **단일 애플리케이션:** 이제 `uvicorn app.main:app` 명령어 하나로 모든 기능(챗봇, 인증, 프론트엔드 서빙)을 포함하는 **완전한 풀스택 웹 애플리케이션**을 실행할 수 있습니다.
- **유지보수성 향상:** 단일화된 코드베이스와 명확해진 아키텍처 덕분에 향후 기능을 추가하거나 문제를 해결하기가 더 용이해졌습니다.
- **완성된 사용자 경험:** 사용자는 회원가입, 로그인, 챗봇과의 실시간 대화 등 애플리케이션의 모든 핵심 기능을 끊김 없이 사용할 수 있습니다.
